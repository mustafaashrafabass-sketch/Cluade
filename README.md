# Almanfz — Electrical & Mechanical Supplies

A bilingual (English / Arabic, RTL) B2B catalog and quotation website for Almanfz, a supplier based in Riyadh. Visitors browse products, build a quote list, upload a BOQ, or contact sales. Every submission is validated on the server and delivered to a configured lead destination.

> **Catalog status:** `data/catalog/` is intentionally **empty**. The existing site, almanfz.com, could not be reached during the build (see [docs/AUDIT.md](docs/AUDIT.md)), and no products were invented. Run the [catalog import](docs/MIGRATION.md) to migrate the real catalog.

## Stack

- **Next.js 16** (App Router, React Server Components) + **TypeScript**
- **Tailwind CSS 4**, with design tokens in `src/app/globals.css`
- **zod** for server-side validation
- Inter + IBM Plex Sans Arabic (self-hosted through `@fontsource`; no runtime calls to Google Fonts)
- No database. The catalog is versioned JSON produced by a repeatable import; leads go to a webhook, email, or a local file store in development
- Tests: Node's built-in test runner (unit) and Playwright (end-to-end)

## Project structure

```

  app/[locale]/…         Pages: home, products, products/[slug], categories, categories/[slug],
                         quote, rfq, about, contact, privacy (+ loading, error, not-found)
  app/api/{quote,rfq,contact}/route.ts   Lead endpoints
  app/sitemap.ts, robots.ts
  proxy.ts               Locale routing + legacy URL redirects (301)
  components/            UI (catalog, quote basket, forms, layout, home)
  lib/catalog/           Types, search/filter engine, server repository
  lib/i18n/              Locale config + full EN/AR dictionaries
  lib/leads/             Validation, upload checks, rate limiting, delivery adapters
  lib/analytics.ts       Consent-aware GA4/GTM events (no personal data)
content/company.json     Verified company details (null fields are hidden)
data/catalog/            Catalog JSON (generated by the import)
scripts/                 import-catalog.ts, validate-catalog.ts, catalog/ adapters
tests/unit, tests/e2e    Tests; tests/fixtures holds synthetic, clearly labelled test data only

```

## Local development

Requires Node.js 20.9+ (22 LTS recommended).

```bash
npm install
cp .env.example .env.local     # optional; development defaults to the file lead store
npm run dev                    # http://localhost:3000 → /en
```

To browse with the synthetic test catalog:

```bash
CATALOG_DATA_DIR=tests/fixtures/catalog CATALOG_IMAGE_HOSTS=legacy.example.test npm run dev
```

In development, submissions are written to `.data/leads/` (git-ignored).

## Deployment

**Vercel (recommended):** import the repository, set the environment variables above for Production and Preview (use `NEXT_PUBLIC_ALLOW_INDEXING=false` on Preview), and deploy. Use `webhook` and/or `email` destinations; Vercel's file system is not persistent.

**Node server / container:**

```bash
npm ci && npm run build
NODE_ENV=production PORT=3000 npm start
```

Put it behind HTTPS (nginx, Caddy or a load balancer) that forwards `Host` / `X-Forwarded-Host` and `X-Forwarded-For`; the same-origin check and rate limiter rely on them. Allow request bodies of at least 11 MB for BOQ uploads.

**After every catalog import:** commit `data/catalog/` (and `public/catalog/images/`), then rebuild so product pages and redirects are regenerated.

**DNS cut-over:** before switching almanfz.com to the new site, run the import with `--download-images` so images no longer depend on the old server, then spot-check `data/catalog/redirects.json` against the old site's most-visited URLs.

## Design and technical decisions

- **B2B quotation basket instead of checkout.** The quote list is stored in `localStorage` (synced across tabs and kept across visits), then submitted with contact details. The server re-resolves every product from the catalog, so the browser can't alter names or SKUs.
- **Honest data.** Prices appear only when the source publishes a non-zero price with a currency; otherwise the product shows "Request Price". No stock, ratings, discounts, testimonials, certifications or statistics are displayed. Product structured data includes `offers` only for real prices and never asserts availability.
- **Server-rendered catalog.** Search, filtering, facets, sorting and pagination run on the server over an in-memory index. The page is a plain GET form, so filters work without JavaScript and can be bookmarked. Small client components only add auto-submit and the mobile filter toggle. Search normalises Arabic letter variants and diacritics, Arabic-Indic digits, `4×16` vs `4x16`, and SKU punctuation.
- **Localisation.** Routes are `/en/…` and `/ar/…`, with `<html lang dir>` set per locale, hreflang alternates and localised metadata. Layouts use CSS logical properties so they mirror in RTL. SKUs, part numbers and prices are isolated as left-to-right (`.ltr-id`). Product text only available in one language is tagged with the right `lang`. The language switcher keeps the current page and query.
- **Legacy URLs.** The importer maps every old product and category URL to its new localised URL; `src/proxy.ts` serves those redirects as 301s.
- **Accessibility.** Includes a skip link, visible focus rings, a native `<dialog>` for the mobile menu (focus trap and Esc), labelled fields with `aria-invalid` and error descriptions, live regions for quote updates, and 44 px touch targets. Reduced-motion preferences are respected.
- **Visuals.** Navy, electric blue and slate, with restrained 4–8 px radii, 1 px borders and subtle shadows. The hero uses a drawn technical illustration instead of stock photography.
